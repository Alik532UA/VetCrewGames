# Vet Crew Games

Набір розвиваючих ігор про тварин. Чотири мови інтерфейсу (`uk`, `en`, `de`,
`nl`), чотири теми.

## Ігри

| Гра                                                                                | Маршрут                                                                                                         | Стан     |
| ---------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- | -------- |
| **Правда чи міф?** — спростування поширених хибних уявлень                         | `/game-mythbusters/`                                                                                            | грається |
| **Кого більше?** — розставити тварин за чисельністю популяції                      | `/game-population/`                                                                                             | грається |
| **Хто з іншої родини?** — знайти тварину з іншої біологічної групи                 | `/game-family/`                                                                                                 | грається |
| **Де живем?** — континенти або природні зони, кілька правильних відповідей         | `/game-habitat/`, `/game-habitat/continents/`, `/game-habitat/biomes/`                                          | грається |
| **Що їмо?** — роздати страви двом тваринам, зайве у смітник                        | `/game-feeding/`                                                                                                | грається |
| **Знайди пару** — класична пам'ять на картках із тваринами                         | `/game-memory/`                                                                                                 | грається |
| **Вікторина** — питання з усіх ігор, соло або кімнатою на кількох                  | `/quiz/`, `/quiz/play/`, `/quiz/online/`                                                                        | грається |
| **Знайди пару на двох** — та сама гра кімнатою, журналом ходів                     | `/pairs/`, `/pairs/online/`                                                                                     | грається |
| **Заповідник** — партія, що триває: бюджет, вольєри, персонал, хвороби, браконьєри | `/reserve/` і чотири біоми: `/reserve/forest/`, `/reserve/tundra/`, `/reserve/savanna/`, `/reserve/rainforest/` | грається |

Плюс `/account/` — необов'язковий профіль: вхід через Google або пошту,
аватарка, пошук людей, підписки й таблиця лідерів. Ігри граються без нього, а
спільні кімнати працюють на анонімному вході.

> Перелік маршрутів тут не декоративний: його звіряє з `LANGUAGE_ROUTES`
> інваріант `src/docs-routes.test.ts`. Нова гра, не описана тут, валить прогін —
> доти цей розділ називав шість ігор із дванадцяти й дві мови з чотирьох.

Концепції ігор і дорожня карта — у `.private/init/`. «Знайди пару» концепції не
має: це класика, додана окремо. Зображення страв і тварин лежать у
`static/images/`; імена файлів страв збігаються з їхніми `id`, і наявність
кожного звіряє інваріант.

Мова живе в адресі: українська на голому шляху, решта за префіксом — `/en/`,
`/de/`, `/nl/`, тобто `/en/game-population/` і так далі. Політика адрес — в
одному модулі [`src/lib/i18n/routing.ts`](src/lib/i18n/routing.ts); посилання
будуються `langPath()`, абсолютні адреси для canonical і sitemap — `langUrl()`.

## Технології

- SvelteKit 2 + Svelte 5 (Runes), TypeScript
- Vanilla CSS, теми через `data-theme`
- Lucide Icons; шість літер, яких немає в основному шрифті, — власними сабсетами в `static/fonts/`
- Firebase Realtime Database — лише для спільної гри й акаунтів; правила доступу лежать у репозиторії й перевіряються гейтом
- GitHub Pages (adapter-static, prerender)

## Перевірки

```bash
npm run check        # svelte-check: 0 помилок і 0 попереджень
npm run lint         # eslint
npm test             # Vitest
npm run check:i18n   # паритет ключів у чотирьох мовах
npm run build        # збірка
npm run check:build  # інваріанти ЗІБРАНОГО build/ — запускати після build
npm run check:rules  # правила доступу до бази над емулятором (потрібна Java)
npm run test:e2e     # Playwright над зібраним сайтом: axe, контраст, локатори
```

`check:build` окремим кроком не випадково: частина дефектів не існує в
джерелах і виникає під час збірки — порожнє тіло сторінки, canonical на чужий
origin, інлайн-скрипт, не покритий хешем CSP. Усі вони в коді виглядають
правильними.

`check:rules` — єдина перевірка, що взагалі бачить правила доступу до бази:
решта гейтів проходить однаково і на правильних правилах, і на «дозволити все».

CSP і теми дивляться на `npm run preview`, а не на `npm run dev`: у dev
політика приходить заголовком, у зібраному сайті — мета-тегом, і поведінка
різна. Прев'ю треба перезапускати після кожної збірки — сервер будує список
файлів на старті.

## Деплой і адреса

Автоматично через GitHub Actions при пуші в гілку `main`.

🌐 **https://alik532ua.github.io/VetCrewGames/** — спільний домен із рештою проєктів, власного тут немає. Звідси дві наслідки, які легко забути:

- `paths.base` дорівнює `/VetCrewGames` у продакшені й `''` у dev, тож шлях, зашитий вручну, зламається на одному з двох;
- `localStorage` спільний із сусідніми проєктами, тому всі ключі обов'язково мають префікс `vetcrewgames_`.

Якщо колись з'явиться власний домен — не міняй `base` наосліп: набір граблів зібраний у [CUSTOM-DOMAIN-v9.md](../sveltekit-canon/selection_criteria/v9/ops/CUSTOM-DOMAIN-v9.md).
