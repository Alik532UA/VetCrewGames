# Архітектура проєкту VetCrewGames

> **Спершу прочитай [PROJECT-CONTEXT.md](PROJECT-CONTEXT.md).** Там персональний
> шар пакета v8: базові параметри, реєстр префіксів на спільному origin,
> прийняті рішення й перелік того, що тут **не** перевіряється автоматично.
> Цей файл — коротка витримка для щоденної роботи.
>
> Загальні стандарти живуть у `sveltekit-canon/selection_criteria/v8`.

## Основний стек

- **Фреймворк:** SvelteKit (Svelte 5)
- **State Management:** Svelte 5 Runes (`$state`, `$derived`, `$effect`) через глобальні класи (напр. `settings.svelte.ts`).
- **Стилізація:** Vanilla CSS (кольорові змінні, теми через `data-theme`).
- **Деплой:** GitHub Pages (Static Adapter).

## Потік даних (Data Flow)

1. Локальний стан компонентів тримається через `$state()`.
2. Глобальні налаштування (тема, мова, шрифт, рахунок) інкапсульовані в класі `Settings` (`src/lib/services/settings.svelte.ts`), який експортує інстанс `settings`.
3. **Збереження — наскрізним записом у мутаторі, а не в `$effect`.** `settings` і
   `logService` — module-level синглтони, і `$effect` у їхньому конструкторі
   кидає `effect_orphan`. Обхід через `$effect.root` тут уже був і був прибраний:
   він дає ефекти, яких ніхто не прибирає, і зберігає те, що щойно прочитав зі
   сховища під час гідрації. Гідрація — у конструкторі; запис — у методі, який
   змінює стан; підписка на зовнішнє джерело — в `init()`, чий cleanup повертає
   компонент-споживач (SVELTE-CORE-v8 § 1.9 і § 2.6).
4. Сховище — лише через фасад `storage` / `sessionStore`
   (`src/lib/services/storage.ts`) з обов'язковим префіксом `vetcrewgames_`.
   Прямий доступ до `localStorage` заборонений правилом ESLint. Фасад **ніколи
   не кидає** і повертає `false`, коли записати не вдалося.
5. Логування відбувається виключно через `logService` (`src/lib/services/logService.svelte.ts`). Прямі виклики `console.log` заборонені. Логер сам редагує PII — на місцях виклику про це думати не треба.

## Стратегія `data-testid` у production

**B — зберігати.** Плагіна, який вирізав би атрибут на етапі збірки, у проєкті
немає, отже де-факто вибрано B — і це записано, а не вдається за A
(TESTID-AND-NAMING-v8 § 1.11). Наслідки, з якими це рішення живе: локатори видно
у продакшн-версії (+0,5–2 КБ gzip і видима внутрішня структура), зате
smoke-тести можна писати проти живого сайту без окремої staging-збірки.

Якщо колись з'явиться плагін видалення — атрибут прибирається **лише** при
`mode === 'production'`, а для `staging`/`preview` лишається, і цей розділ
оновлюється разом із кодом.

## Специфічні правила та конвенції

- **Сховище:** Завжди використовуй префікс `vetcrewgames_` для будь-яких ключів в `localStorage` та `sessionStorage`.
- **Локалізація:** Усі тексти в UI мають проходити через систему i18n (`src/lib/i18n/index.ts`). Не хардкодь рядки в `.svelte` файлах. Це стосується й `aria-label`: його не видно на екрані, але його читає скрінрідер.
- **Мова живе в АДРЕСІ.** Маршрути лежать під `src/routes/[[lang=lang]]/`: українська на голому шляху, англійська за `/en/`. Уся політика адрес — в одному модулі `src/lib/i18n/routing.ts`; звідти беруться `langPath()` для посилань і `langUrl()` для canonical/hreflang/sitemap.
- **Посилання НЕ склеюються з `base`.** Внутрішні — через `langPath()` (усередині типізований `resolve()`), активи — через `asset()`. Під час prerender `base` **відносний**, тож `${base}/en/` на сторінці `/game-population/` дає `/VetCrewGames/game-population/en/`. Тримає це інваріант у `src/structure.test.ts`.
- **`aria-label` НЕ обгортається у `formatPlain()`.** Ця функція міняє кириличну «і» на латинську «i», щоб літера була у шрифті inglobal. Для того, що малюється, — правильно; для того, що читає машина (заголовок вкладки, підпис для скрінрідера), — ні: «Змiнити» з латинською i вимовляється як покруч.
- **Теми:** Тема перемикається через `data-theme` на `documentElement`. Доступні теми: `dark`, `light-green`, `winter`, `orange-purple`. Зверни увагу, що ми блокуємо мобільний "Force Dark Mode" мета-тегом `<meta name="color-scheme" content="light dark" />`, який оновлюється динамічно (для темних тем він стає `dark`).
- **Іконки:** Використовувати тільки `lucide-svelte`. Системні емодзі (🌞, 🌙) заборонені в UI через неузгодженість між платформами.
- **Версіонування:** Проєкт використовує автоматичне підняття версії. Поточна версія експортується в `static/app-version.json`.
- **Збірка:** Жодних кастомних скриптів у корені проєкту, всі такі скрипти розміщуються у папці `scripts/`.

## 🚫 Жорсткі обмеження (Anti-patterns - НЕ РОБИ)

- **Svelte 4 APIs:** КАТЕГОРИЧНО заборонено використання старих API Svelte 4: `writable`, `readable`, `on:click`, `<slot>`, `export let`. Завжди використовуй `$state`, `$derived`, `$props`, `onclick`, `{@render ...}`.
- **Console.log:** Заборонено використання `console.log`, `console.warn`, `console.error` для бізнес-подій. Використовуй `logService`.
- **Локалізація:** Заборонено хардкодити тексти інтерфейсу в шаблонах, завжди використовуй i18n (`src/lib/i18n`).

## 💡 Приклади правильного коду (Svelte 5 Runes)

### 1. Компонент Svelte 5

```svelte
<script lang="ts">
	let { title, count = 0 }: { title: string; count?: number } = $props();
	let localState = $state(0);
	let doubled = $derived(localState * 2);

	function handleClick() {
		localState++;
	}
</script>

<button class="btn" onclick={handleClick}>
	{title}: {count} + {localState} (x2: {doubled})
</button>
```

### 2. Глобальний реактивний клас (Сервіс)

```typescript
class SettingsService {
	theme = $state<'dark' | 'light-green' | 'winter' | 'orange-purple'>('dark');
	private themes: Theme[] = ['dark', 'light-green', 'winter', 'orange-purple'];

	toggleTheme() {
		const currentIndex = this.themes.indexOf(this.theme);
		const nextIndex = (currentIndex + 1) % this.themes.length;
		this.theme = this.themes[nextIndex];
	}
}
export const settings = new SettingsService();
```

## 🪤 Локальні пастки

| Пастка | Що саме |
|---|---|
| Порти — **5192** (dev) і **5191** (перегляд збірки) | конфігурації `vetcrew-dev` і `vetcrew-preview` у `.claude/launch.json` кореневої теки `GitHub`, обидві зі `--strictPort`. Доти запису не було зовсім, і `vite dev` ішов на типовий 5173 — спільний з усіма сусідами, тож можна було дивитись чужий сайт і не помітити |
| CSP перевіряється лише на **зібраному** сайті | у dev політика приходить заголовком, у пререндері — мета-тегом, і поведінка різна. Дивитись треба `npm run preview`, а не `npm run dev` |
| `base` різний у dev і production | `svelte.config.js`: `NODE_ENV === 'production' ? '/VetCrewGames' : ''`. Тобто локально застосунок за коренем, а на Pages — за префіксом. Шлях, зашитий вручну, зламається на одному з двох |
| Playwright тут **не стоїть** | `playwright.config.*` у проєкті немає. Не створюй файлів під нього — вони не запустяться, і ніхто про це не повідомить (AI-AGENT-PITFALLS-v8 § 1.3) |
| Мета-тег `color-scheme` рухомий | він оновлюється динамічно під тему, щоб заблокувати мобільний Force Dark Mode. Статичне значення поверне баг |
| `vite preview` не бачить файлів, створених ПІСЛЯ старту | сервер будує список файлів один раз. Після нової збірки при живому прев'ю сторінка 404-ить на нових хешах бандла, і це виглядає як зламана збірка. Прев'ю **перезапускати** після кожного `build` |
| Інлайн-скрипт у `app.html` стоїть **нижче** `%sveltekit.head%` | мета-політика CSP діє лише на те, що після неї. Пересунути скрипт вище — і його хеш перестане щось означати. Хеш рахує `svelte.config.js` із самого файлу, з нормалізацією `\r\n` → `\n`: браузер хешує вже нормалізований текст, тож без цього на Windows-чекауті хеш не збігається ніколи |
| `page.url.searchParams` під час prerender **кидає** | «Cannot access url.searchParams on a page with prerendering enabled» валить збірку. Читання query-параметрів guard-иться `browser` з `'$app/environment'` |
| `resolve()` НЕ додає кінцевого слеша | а тут `trailingSlash: 'always'`. Нормалізація живе в `langPath()`; без неї кожне посилання — редирект, і форма адреси розходиться з canonical |
| «Хвіст» адреси береться з `page.route.id`, а не з `pathname` | у `pathname` є `base`, а він під час prerender відносний — відрізати його нічим |
| Текст `<style>` чи `<script>` у коментарі всередині `script` ламає `svelte-check` | компілятор такий файл збирає без слова, `svelte-check` каже «`script` was left open» на весь файл. Назви тегів у коментарях — без кутових дужок |
| У прихованій вкладці браузера анімації НЕ йдуть | `requestAnimationFrame` не спрацьовує, переходи Svelte замерзають, вихідні вузли лишаються в DOM. Плюс `setTimeout` клампиться до ~1 с, тож подвійний клік «не спрацьовує». Автоматична перевірка має дивитися на стан контролера, а не на кількість вузлів |

## ✅ Команди перевірки

```
npm run check       # svelte-check, має бути 0 помилок і 0 попереджень
npm run lint        # eslint
npm test            # Vitest
npm run check:i18n  # паритет ключів у двох мовах
npm run build       # збірка
npm run check:build # інваріанти ЗІБРАНОГО build/ — запускати ПІСЛЯ build
```

**Читай підсумок збірки, а не відфільтрований вивід.** `npm run build | grep
"✓ built"` показує зелений рядок і на впалому прогоні: помилка prerender
друкується нижче, а `build/` лишається від попередньої вдалої збірки, тож
`check:build` теж проходить. Дивитися треба код виходу (AI-AGENT-PITFALLS-v8
§ 5.6). Цей самий обман уже спрацював тут одного разу.

**Результат треба побачити, а не припустити.** Твердження «правило виконано»
робиться після прогону, а не замість нього (AI-AGENT-PITFALLS-v8 § 5.1).
